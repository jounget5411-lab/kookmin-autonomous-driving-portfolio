# 측정 조건과 구현 범위

[프로젝트 소개로 돌아가기](../README.md) · [문제 해결 사례](engineering-cases.md)

구현 구조는 보관 저장소의 `8036461664402a54821b0665a4434e961f9a2e76` 커밋과 본선 V7 설정에 근거합니다. 대회 성과와 개발 중 실험은 프로젝트 기록을 기준으로 정리했습니다. 문서 제작 과정에서 차량 주행·모델 평가·ROS 빌드를 다시 수행하지는 않았습니다.

## 대회 성과

| 항목 | 대회 후 기록 |
|---|---|
| 본선 | 2026.08.25 |
| 진출 | 예선 130팀 중 22팀 본선 진출 |
| 최종 결과 | 전체 코스 완주 · 8위 · 비수상 |
| 주행 기록 | 본 주행 135초, 접촉 감점 반영 155초 |
| 남은 문제 | 라바콘 접촉과 추월 차량 접촉 |

순위와 시간은 대회 후 기록에 근거합니다. 접촉 없이 완주했다거나 추월 CNN만으로 전 코스를 주행했다는 의미는 아닙니다.

## 모델 평가: 학습 적합도와 독립 평가 구분

일반 주행 모델은 연속 프레임이 학습과 평가에 섞이지 않도록 시퀀스 단위로 나눈 기록이 있습니다. 나머지 세 모드의 수치는 학습 데이터에 대한 적합도이며, 독립 장면에서의 성능으로 해석하지 않습니다.

| 모델 | 데이터 구성 | 기록된 경로 MAE | 해석 |
|---|---|---|---|
| GENERAL | train 1,731 / validation 178 / test 321장 | **test 8.045 cm** | 분리한 테스트 데이터 평가 |
| SHORTCUT | 928장, 전체 학습 사용 | training-fit 2.846 cm | 학습 데이터 적합도 |
| OVERTAKE | 508장, 전체 학습 사용 | training-fit 1.717 cm | 학습 데이터 적합도 |
| CONE | 967장, 전체 학습 사용 | training-fit 3.686 cm | 학습 데이터 적합도 |

이 오차는 데이터셋의 정답 경로와 모델 예측 경로 사이의 차이입니다. 차량의 실제 횡방향 추종 오차, 무접촉 주행률, 신호등 인식 정확도와는 다른 지표입니다.

최종 코드의 공통 입력은 노란선·흰선·LiDAR로 구성된 `3 × 128 × 120` BEV입니다. 경로는 전방 0.3–3.0 m의 고정 위치 28개를 기준으로 표현합니다. 실행 시 유효도와 경로 조건을 통과한 구간만 차량 제어에 전달하므로, 모든 `/center_path` 메시지가 항상 28개 점을 포함하는 것은 아닙니다.

## 지연과 처리율의 측정 조건

| 대상 | 개발 기록 | 범위 |
|---|---|---|
| YOLO 실행 방식 비교 | PyTorch p50 91.76 ms → OpenVINO p50 51.03 ms | 같은 녹화 프레임을 사용한 모델 비교 |
| 자원 경합 관찰 | 단독 실행 약 50 ms / 실주행 평균 약 181 ms | 실행 부하와 집계 방식이 다른 관찰값 |
| 경로 생성 파이프라인 | `/center_path` 11.948 Hz, camera-to-path p50 약 114.5 ms | **2026-08-21, 뷰어·브리지 제외 조건** |
| 초기 현장 관찰 | 경로 갱신 약 2 Hz | 수동 관찰이며 위 계측과 동일 조건 비교가 아님 |
| 모터 제어 | 20 Hz, 속도 상승량 0.25/tick | 제어 설정값 |
| 가속 변화 | 속도 명령 0→12에 약 2.4초 | 설정에 따른 명령 변화 시간 |

경로 발행률과 센서 입력부터 결과까지의 지연은 서로 다른 값입니다. 2 Hz를 정확히 500 ms의 인지 지연으로 환산하거나, 초기 관찰과 후반 계측을 동일 조건의 6배 개선으로 표현하지 않습니다. 11.948 Hz 또한 신호등 2단 분류기를 포함한 최종 대회 구성 전체의 처리율로 사용하지 않습니다.

`speed_cmd`는 차량 명령값입니다. 별도 속도 보정 없이 km/h로 환산하지 않습니다.

## 최종 V7과 개발 과정의 구분

- 예선은 2차곡선 피팅과 상태 머신 중심이며 본선 V7은 BEV·CNN 경로 생성 중심입니다.
- 네 가지 모델을 준비하지만 매 입력에서 활성 모드의 모델 하나만 추론합니다.
- 최종 장애물 회피 전략은 `hardcoded_all`입니다. 조향 블록 실행 중에는 경로 CNN의 모드를 GENERAL로 유지하며 제어 노드가 조향을 배타적으로 담당합니다.
- 신호등은 검출한 박스에 별도 분류기를 적용합니다. 조도·거리·흔들림 조건을 포괄하는 최종 정확도는 충분히 평가하지 못했습니다.
- 모드 종료와 추월 블록이 시간에 의존하므로 실제 이동 거리·차량 속도가 달라지는 환경에 대한 일반화에는 한계가 있습니다.
- 경로 생성은 입력 시각·형식·유효성을 검사하지만, 제어는 새 경로를 받지 못하면 이전 유효 경로·조향을 유지할 수 있습니다. 경로 유실이 자동 정지를 뜻하지 않습니다. 이는 대회 실험 환경의 정책입니다.
- `race_finish_enabled`는 `false`입니다. 자동 랩 종료는 최종 활성 기능이 아닙니다.

## 이미지의 범위

- 대표 이미지와 V7 구조도는 소스에 근거해 새로 그린 개념 그림입니다.
- BEV 비교와 경로 보정 도구는 프로젝트 개발 기록에 수록된 화면을 원본 그대로 사용했습니다.
- 비교 화면의 셀 수나 도구 화면의 샘플 수는 해당 프레임·작업본의 값입니다. 전체 데이터셋 규모나 최종 모델 성능을 대신하지 않습니다.

[근거 코드와 기록의 구분](source-guide.md)에서 각 설명에 연결된 자료를 확인할 수 있습니다.
