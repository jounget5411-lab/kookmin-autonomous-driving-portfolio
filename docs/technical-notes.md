## 경로 모델과 데이터 구성

일반 주행 모델은 주행 시퀀스 단위로 데이터를 분리해 평가했습니다. 지름길·추월·라바콘 모델은 각 상황에 맞는 데이터를 구축해 학습했습니다.

| 모델 | 데이터 구성 | 경로 예측 MAE | 평가 데이터 |
|---|---|---|---|
| GENERAL | train 1,731 / validation 178 / test 321장 | **8.045 cm** | 별도로 분리한 테스트 321장 |
| SHORTCUT | 학습 928장 | 2.846 cm | 학습 데이터 |
| OVERTAKE | 학습 508장 | 1.717 cm | 학습 데이터 |
| CONE | 학습 967장 | 3.686 cm | 학습 데이터 |

경로 예측 MAE는 데이터셋의 정답 경로와 모델 예측 경로 사이의 평균 절대 오차입니다.

공통 입력은 노란선·흰선·LiDAR로 구성된 `3 × 128 × 120` BEV입니다. 경로는 전방 0.3–3.0 m의 고정 위치 28개를 기준으로 표현하고, 유효도와 경로 조건을 통과한 구간을 차량 제어에 전달합니다.

## 지연과 처리율의 측정 조건

| 대상 | 측정값·설정값 | 조건 |
|---|---|---|
| YOLO 실행 방식 비교 | PyTorch p50 91.76 ms → OpenVINO p50 51.03 ms | 같은 녹화 프레임을 사용한 모델 비교 |
| 경로 생성 파이프라인 | `/center_path` 11.948 Hz, camera-to-path p50 약 114.5 ms | **2026-08-21, 뷰어·브리지 제외 조건** |
| 모터 제어 | 20 Hz, 속도 상승량 0.25/tick | 제어 설정값 |
| 가속 변화 | 속도 명령 0→12에 약 2.4초 | 설정에 따른 명령 변화 시간 |

최신 프레임 버퍼, 필요한 토픽만 연결하는 브리지, 공유 메모리 전송으로 추론과 영상 전송의 자원 경합을 줄였습니다. 모터 제어에서는 차량 명령값 `speed_cmd`의 변화량을 제한해 가속을 부드럽게 처리했습니다.

## 본선 V7 설계

- **BEV 기반 경로 생성:** 예선의 2차곡선 피팅과 상태 머신을 카메라·LiDAR 융합 및 CNN 경로 생성으로 확장했습니다.
- **상황별 모델 선택:** 일반·지름길·추월·라바콘 모델을 미리 로드하고 현재 모드의 모델 하나를 추론합니다.
- **추월 제어:** `hardcoded_all` 전략으로 LiDAR 기반 장애물 방향 판단과 고정 조향 시퀀스를 결합했습니다. 조향 블록 실행 중에는 경로 CNN의 모드를 GENERAL로 유지하고 제어 노드가 조향을 배타적으로 담당합니다.
- **2단 신호등 인식:** 검출한 신호등 영역에 별도 분류기를 적용하고, 신호등이 없는 프레임에서는 분류 연산을 생략합니다.
- **입력 검증:** 시각·형식·유효도를 확인한 경로를 제어 노드에 전달합니다.
- **제어 명령 일원화:** 경로 추종·추월·가감속 처리를 `simple_motion`에서 통합하고 `/xycar_motor`로 발행합니다.
